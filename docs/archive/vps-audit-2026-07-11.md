Host: `<origin-ip>` (`vps-b3b8450d`), Ubuntu 24.04.4, uptime ~20 days.

## Verified good

- PostgreSQL and Redis bind to loopback only; UFW default-denies inbound traffic.
- HTTP/HTTPS are exposed through nginx; ports 3000 and 8080 are UFW-denied.

- `/opt/resume-ai/.env` is mode `600`, owned by root.
- No production vulnerabilities were returned by `npm audit --omit=dev`.

## Findings and actions

1. **High priority — root SSH exposure.** SSH is open globally and `PermitRootLogin without-password` plus `PasswordAuthentication yes` leaves a root login surface under continuous brute-force traffic. Use a non-root admin, disable password authentication, restrict SSH by source/VPN, and keep fail2ban.
2. **High priority — web and worker services run as root without sandboxing.** `resume-web` and `resume-worker` have no `User`, `NoNewPrivileges`, `PrivateTmp`, `ProtectSystem`, `ProtectHome`, resource limits, or capability reduction. Create a dedicated service account and add systemd hardening before treating an app compromise as contained.
3. **High priority — backups are not working.** The configured cron redirects to `/opt/resume-ai/data/backups`, but that directory does not exist. There was no backup file to verify. Create the directory with restrictive ownership, encrypt/off-host backups, and perform a restore test.
4. **Medium — patch drift.** `apt-get -s upgrade` reports pending updates including `cloudflared`, `curl`, `libcurl`, `apparmor`, and kernel-adjacent packages. Apply updates in a maintenance window and reboot when required.
5. **Medium — direct origin is reachable.** A direct HTTPS request to the origin returned `200`. Because nginx does not overwrite `CF-Connecting-IP`, application rate limits can be bypassed by forging that header. Restrict 443 to Cloudflare IP ranges, use a tunnel, or derive client IP only from a trusted proxy hop.
6. **Medium — extra root-owned service on 0.0.0.0:8080.** A Node `antigravity-claude-proxy` process is listening on all interfaces. UFW currently denies 8080, but verify it is required, bind it to loopback, and run it as a dedicated user.
7. **Medium — PostgreSQL TLS is off.** It is loopback-only, so this is defense-in-depth; keep it private and use TLS if access expands beyond localhost/container networking.
8. **Low — nginx global config advertises TLS 1.0/1.1 before vhost overrides.** The RoleSharp vhost restricts TLS to 1.2/1.3, but remove obsolete global defaults to avoid unsafe behavior in future vhosts.

## Remediation status — 2026-07-11

- Deployed application security migration and code fixes successfully.
- `resume-web`, `resume-worker`, and `rolesharp-jobs` now run as `rolesharp` with systemd sandboxing and resource limits.
- Claude proxy now runs as `claudeproxy` and binds only to `127.0.0.1:8080`.
- Nginx real-IP handling trusts `CF-Connecting-IP` only from published Cloudflare networks; the application now keys rate limits from nginx-overwritten `X-Real-IP`.
- Global nginx protocols are restricted to TLS 1.2/1.3 and configuration validation passes without duplicate-vhost warnings.
- A local PostgreSQL custom-format backup and daily backup cron are installed and verified.

Still pending explicit operational approval: create/test alternate non-root SSH access and disable root/password login; restrict ports 80/443 to Cloudflare networks; apply OS updates/reboot if required; encrypt/copy backups off-host and perform a restore drill. Direct-origin HTTPS therefore remains reachable until the firewall step is approved.
